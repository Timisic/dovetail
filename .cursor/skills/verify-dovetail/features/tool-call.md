# One tool call

## Sub-features

Fresh start runs a fixed greeting request through starter code and shows the invocation, result, and final response. Resume runs current learner code and reports its actual result, including syntax failure. The challenge matches the requested name with a loop, forwards arguments, and errors for an unknown name. Chat code or precise logic is applied through inspect and source-checked apply with automatic tests. Answer assistance is explicit. Pause and restart retain learner code and checkpoint. Each active request context contains the actual teaching skill and fresh saved facts without persisting a teaching message.

## How to get to it (user POV)

Launch your configured `pi -e /absolute/path/to/dovetail` in the learner's working directory. Enter `/dovetail start`. On a fresh project, observe `Hello, Ada!` and the absolute code path; when resuming, use the actual execution feedback. Edit that file or provide code in chat, then ask to test. Enter `/dovetail status`, `/dovetail off`, and `/dovetail start` to inspect, pause, and resume.

## Driving it with Node RPC

Run `node --test --test-reporter=tap test/*.test.mjs > .local/verification/tests.tap` and `node test/verify.mjs` from the repository, after creating `.local/verification`. The first command runs the learner's source and actual Pi-loaded tool adapter. It checks passing greet requests for Ada and Lin, the unknown weather failure, applying loop code, syntax errors, explicit assistance, corrupt state, stale source, cancellation, bounded execution, and preserved sentinels.

Storage checks also preserve old `.tmp` files and abandoned stages, kill instrumented bootstrap children before publication and after root visibility, and reject an editor write made by an actual filesystem watcher while source staging is held by a child preload. Conflict keeps both the external source and checkpoint unchanged, cleans only the owned stage, and permits a source-refreshed retry. Loader context checks apply within the same turn, then verify fresh source/check facts, exactly one hidden custom teaching message, no teaching `sendMessage`, unchanged input and other messages, and removal while paused or invalid. The historical review logs are `.local/verification/review-before.tap` and `review-after.tap`; source comparison evidence is `hash-after.tap` and `tests.tap`. Focused tests cover read-only valid version 1 migration for paused/active state, preserved assistance and exact source bytes, a genuine version 2 check on resume, malformed legacy/new and unknown checkpoints, same-length edits with restored timestamps, and a saved executed snapshot that remains stale after a disk-only restart.

The helper starts installed Pi in isolated RPC mode, checks Dovetail and skill discovery, drives start and status, edits the actual learner file, and exits. It relaunches with no saved conversation, reads the resume message, drives off and start, and compares source bytes and checkpoint mode. Successful evidence includes actual greeting output, retained edited source, a paused checkpoint snapshot, and no `agent_start` or `extension_error` events.

## Gotchas

RPC does not exercise context conversion during a model turn, live model interpretation of chat, or interactive TUI rendering. Context assertions call the actual loader-registered handler directly. The adapter test applies the exact few lines a tutor would translate from precise loop logic; it does not claim a real provider translated them. Do not send normal chat in this credential-free check. The deterministic example uses a scripted request and response. Runs execute trusted learner code with a timeout and bounded output; they are not a security sandbox. Use one Pi process per workspace. Malformed or unrelated existing state requires inspection, not automatic reset. Ordinary editor metadata in a valid project is preserved. Source publication uses optimistic revalidation; an uncooperative process can still write after the final check and before rename. Concurrent first-start publication also has an absence-check/rename race. Unique staging does not provide strict cross-process compare-and-swap or power-loss durability.
